# UI改善の実装と検証状況

2026-11-07。基準は output/ui-audit/ui-specification.md と implementation-conformance-review.md。

## 実装した残件

- 部内ゲームの選手選択に記録先チーム名を表示。
- 主記録60px・間隔8px、戻る・相手得点・成績切替・閉じる48px以上へ調整。
- 選手名16px、注記・上部タブ14px、時計28pxへ調整。
- 上部タブとタイムアウトに意味の切れ目の改行候補を追加。読み上げの名前は改行候補に左右されないラベルで指定。
- 選手→シュート種別→選び直しで、各段階の見出しへフォーカスを移す。
- 相手の得点にも見出しフォーカスと起点への復帰を追加。
- 復元した通常プレーの下書きでも起点ボタンを取得する。画面の再描画で復帰先の参照が消えないようにした。
- 保存後・キャンセル後の復帰を既存テストに追加。保存・時刻・集計処理は維持。

## 実施した確認

最新の追加変更で自動テスト11ファイル48件が成功。これはUI条件48個の網羅を意味しない。

ローカル試用はFirebase設定をプロセス内で無効化し、本番データへ接続せず実施。

| 条件・操作 | 結果 |
|---|---|
| 40人名簿、最大40文字の選手名 | 40人を選択肢に表示。幅320pxでdialogのclientWidth/scrollWidthとも250px、横はみ出しなし |
| 相手名80文字 | 入力・試合作成・記録画面まで操作。幅320pxのページclientWidth/scrollWidthとも305px |
| 40人名簿の末尾の選手不明 | 到達し、シュート種類へ遷移可能 |
| 選手を選び直す | 見出し「選手を選ぶ」にフォーカス、dialogスクロール位置0 |
| 相手の背番号不明→種類→閉じる | 相手のシュート決ボタンにフォーカス復帰 |
| 通常シュートを保存 | 元のシュート決へフォーカス復帰。ブラウザーと自動テストで確認 |
| キャンセル | 元の記録ボタンに復帰。自動テストで確認 |

以前の実施分：12人の成功シュート／リバウンド全選手の座標一致、失敗・パスカット先頭位置一致、390×844で結果の最初の行がページ上端から755～約796px、320pxの長い名前を含む結果表の横はみ出しなし、Q終了→試合終了→次試合準備。

主要な配色の相対輝度から計算した比：本文 #202b24/白14.66:1、注記 #627066/白5.21:1、選択文字 白/#244d35 9.60:1、タブ文字 #234b39/#e7f0e8 8.44:1。フォーカス輪郭 #c07920/白3.50:1。これらの組み合わせの計算であり、全画面・全状態の適合宣言ではない。

## 未実施の確認

実装済みと検証済みを区別するため、以下を未確認として残す。

- 200%文字拡大、画面回転、最大経過時間・3桁得点を同時に表示した試験。
- 5人・20人、0/00/99、部内ゲーム3モード、通信失敗時について、新しいレイアウトでの全条件の実画面確認。
- ページを読み直した下書きからのフォーカス復帰（対応コードは追加済み）。
- 変更後の全画面に対するPDF/印刷・ゴミ箱の表示回帰。
- 実スマホのキーボード、VoiceOver/TalkBack、体育館での片手操作、利用者による課題確認。
- 本番で配信されるコミットとの照合・公開確認。

上記のうち、ブラウザーやローカルで確認できる項目も残っている。すべてが利用者の操作待ちという意味ではない。計画全体の完了はまだ宣言しない。
