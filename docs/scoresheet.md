# TOスコアシートと印刷

試合終了後の「スコアシート」で、A4縦の帳票を表示します。「PDFを保存」でダウンロード、「印刷・印刷用画面」でブラウザの印刷機能を開きます。出力はスコアシート・選手別成績・両方から選べます。印刷時はA4、倍率100%、ブラウザのヘッダーとフッターをオフにしてください。印刷機能を持たないアプリ内ブラウザでは、保存したPDFを端末のPDFビューアで開いて印刷できます。

## 記録方法

- 従来のシュート、リバウンド、パスカットに「ファウル」「タイムアウト」「出場」を追加しました。相手も同じ画面で選択できます。
- 出場は各選手の初出場だけを入力します。先発5人は「スコアシート情報」で設定します。
- タイムアウトだけは会場の時計の残り時間を入力します。アプリの経過時計は競技時計ではないため自動換算には使いません。中学8分・延長3分、高校10分・延長5分、任意設定を選べます。
- Q間のファウルは次のQに入力できます。次のQの記録がある場合、試合を終了する前にそのQを開始するか記録を訂正・取り消します。延長のチームファウルは第4Qに加算します。
- 後から「記録を確認・訂正する」で取消、記録漏れの追加、同一Q内の順序変更ができます。ランニングスコアはその順序から再計算します。

## 空欄と確認済み

大会・会場・担当者、選手のライセンス下3桁、CAP、先発、コーチを試合ごとに保存できます。既存試合の不足情報を自動で推測・書き換えしません。各チームの名簿・出場・ファウル・タイムアウト・得点について、確認済みを指定した項目だけ締め線等を付けます。未確認事項は画面と補足ページに表示します。署名は印刷後に手書きします。

## 帳票の範囲

ユーザー提供の「JBA TOマニュアル ハンドブック（2024年4月1日）」のチーム欄・ランニングスコア・結果欄を参考に、部内で振り返るための2024年様式を再現しています。罫線はSVGとPDFで同じ図形データを使います。登録18人・累計160点を超える情報は続紙に出力し、捨てません。シュート成功/試投、リバウンド、パスカットは別紙に集計します。

P/T/U/D/F、コーチC/B/M、GDとFT付記1/2/3/cを入力できます。累積T/UとコーチC/BによるGDは自動付記します。複雑な退場・ファイティング等の処置は自動判定しません。個別の記号・補足を保存し、必要なら印刷後に競技規則に合わせて追記してください。大会提出書類としての認定や、競技時計・審判判断との連動はありません。

## 保存とオフライン

新しい記録も既存の送信待ち保存を使います。順序変更は全件を端末内に保存してから同期を開始します。クラウドへの各記録の反映は順次行うので、1試合1端末で操作し「すべて保存済み」を確認してから別端末で出力してください。

PDFは端末内で作成し、外部のPDF変換サービスへ送信しません。日本語フォント約5.8 MBを初回に取得し、その後オフライン用にキャッシュします。初回のPDF作成は通信可能な場所で行ってください。未対応文字がある場合は文字欠落のPDFを作らず、印刷用画面を案内します。

## 参照資料・フォント

- 帳票欄の参考：[JBA スコアシート印字ツール](https://www.japanbasketball.jp/files/to/manual/2022inji_tool_fix.xlsx)。元の画像はアプリに同梱せず、罫線と欄を実装しています。
- 日本語フォント：[Google Fonts Noto Sans JP](https://github.com/google/fonts/tree/main/ofl/notosansjp)。可変フォントのwght=400を静的化し、`public/fonts/NotoSansJP.ttf` として同梱。ライセンスは同ディレクトリの `OFL.txt`。
- PDFはフォント全体を埋め込みます。部分埋め込みでは実際の描画で欠字が発生したため使用していません。

`RENDER_SHEET_FIXTURES=1 npm test` で架空試合のPDFを `tmp/pdfs/` に生成できます。得点順序、同時刻への挿入、取消、延長、旧データ、出場、タイムアウト、Firestoreルールに加え、生成PDF全ページを画像化して目視確認しています。
