バスケ部 試合記録アプリ 開発計画

作成日: 2026-11-01。同日のユーザー指示で開発を開始し、メール不要の初版を公開した。最新の接続・公開状況はsetup.mdを参照。

**目的と確定事項**

スマホを持ったマネージャーが、試合を見ながら少ない操作で自チームのプレーを記録する。部活ごとにチームを作成してデータを共有し、1試合の入力は1台のスマホで行う。

- 選手の名前と背番号を事前に登録する。
- クォーターごとの経過時間を00:00から表示する。Qの制限時間は設定しない。
- ボールが外に出たとき、ファウル、タイムアウト等の中断も含めて計測を続け、Qの終了を手動で指定する。
- シュート成功・失敗、リバウンド、パスカットを記録する。
- シュートは2点・3点・フリースローを区別する。
- 試合後にプレー一覧を確認し、過去の試合も閲覧できる。
- 公開先はVercel、データ保存先はFirebase。無料枠から始める。
- 白背景、読みやすい文字、大きなボタンを基本にする。
- 開発のまとまった段階でGitHubへcommit・pushする。
- 最初の画面は「チームを作成」「チームに参加」の2ボタンだけにする。
- 作成・参加は合言葉だけで行い、メールアドレスの入力や手作業でのユーザー登録を求めない。
- すでに使用中の合言葉ではチームを作成できない。同時作成でも重複を防ぐ。
- 同じチームの利用者全員が同じ閲覧・編集権限を持ち、別チームの記録は読めない。
- 2026-11-01にユーザーから開発開始の指示を受領した。

**初版の範囲と仮置き**

自チームのみ記録し、選手名簿を次の試合にも再利用する想定。各Qを手動で開始・終了し、最後に試合終了を指定する。Q数や制限時間による自動終了は設けず、追加の区間も同じ操作で記録できる設計案とする。相手チームの得点入力、交代・出場時間、ショットチャート、グラフ、通知、ランキングは初版に含めない。試合結果は記録一覧を基本とし、集計表の追加は必要になった時点で相談する。

**画面と操作**

| 画面 | 内容・操作 | 完了条件 |
| --- | --- | --- |
| 入口 | チームを作成／チームに参加の2ボタン | 最初にメールアドレス等を求めない |
| 作成・参加 | 合言葉1つを入力 | 重複作成を拒否し、参加先チームだけのデータへアクセスできる |
| ホーム | 「新しい試合」「選手登録」、進行中の試合、過去の試合一覧 | 日付・対戦相手から対象試合を選べる |
| 選手登録 | 名前・背番号の追加、変更、非表示化 | 同じ試合内の背番号重複を防げる |
| 試合準備 | 日付、対戦相手、ベンチ入り選手の選択 | 時間設定なしで選手と試合設定を確認して開始できる |
| 試合記録 | Q・経過時間、Q開始/終了、4種類の記録ボタン、直前の記録、訂正入口 | リバウンド等は2タップ、シュートは3タップで登録できる |
| 選手選択 | 背番号を大きく表示した「背番号＋名前」のボタン | 選手を選ぶか、キャンセルして元へ戻れる |
| シュート種別 | 「2点」「3点」「フリースロー」の3ボタン | 選択で保存し、記録画面へ自動で戻る |
| 試合詳細 | Q・経過時間・選手・プレーの時系列一覧、訂正 | 再訪問・別端末でも同期済みの記録を閲覧できる |

選手ボタンの順序は背番号順で固定し、直近の操作などによって入れ替えない。名前が長い場合の折り返しを考慮し、背番号は文字列として扱って「0」と「00」を区別する。最終登録時に該当試合の選手であることを検証する。

**記録の具体例**

1. 「シュート決」を押す。この瞬間のQと経過時間を仮記録する。
2. 「7 田中」を押す。
3. 「3点」を押す。
4. 「第2Q 開始から05:32 / 7 田中 / 3点シュート成功」を保存し、元の画面に戻す。

リバウンド・パスカットは種別選択が不要なので2タップで完了する。選手選択中も試合時計は進む。保存する時刻は最初にプレーボタンを押した瞬間とし、選手選択にかかった時間は加えない。キャンセルした操作は記録に残さない。

通常の記録ごとに確認ダイアログは出さない。選択画面で戻る操作と、記録済みデータの訂正は分ける。最終ボタンの連打で同一操作が二重保存されないよう、1操作に1つのIDを付ける。一方、同じ選手の連続プレーは別操作として正常に記録できるようにする。

直前の記録には「取り消す」を付ける。履歴から選手、プレー種別、Q・時刻の訂正も可能にする。取り消しは内部的に取消状態を保存し、通常一覧から除外する。訂正中も計測中の時計は動き続ける。

**タイマー**

- 状態を「準備中」「Q計測中」「Q間」「試合終了」で管理する。
- 「試合開始」で第1Qの00:00からカウントアップする。
- ボールアウト、ファウル、フリースロー、タイムアウトでも時計を止める操作は不要。中断を含む実際の経過時間として記録する。
- Qの長さを指定する項目、カウントダウン、自動停止は設けない。8分や10分を超えても進む。
- 「このQを終了」で計測を止め、「次のQを開始」でQ番号を進めて00:00から計測する。
- Q間の休憩は前後のQの経過時間に含めない。休憩用タイマーは作らない。
- 通常の試合中画面にプレー中断ごとの停止・再開ボタンは置かない。会場の公式時計に合わせる機能も不要。
- 未確定のプレーを確定またはキャンセルしてからQを終了する。Q間は通常の新規プレー入力を無効にし、履歴の訂正は可能にする。
- Q終了の誤操作に備え、次のQの開始前なら直前のQ終了を取り消せる設計案とする。再開時は元の開始時刻からの経過時間へ戻す。
- 試合終了は通常ボタンから離して配置し、終了前に確認する。終了後の画面では新規プレー入力を止め、履歴の訂正を可能にする。
- 必要な追加区間も「次のQを開始」で計測できる設計案とし、延長時間の事前指定を求めない。

時計は1秒ごとのカウントを積み重ねず、「現在時刻 − Qの開始時刻」から算出する。Q終了後は「Q終了時刻 − Q開始時刻」で確定する。画面更新が遅れても時間表示を再計算できる設計にする。Q開始・Q終了・終了取消・試合終了時に状態を永続化し、毎秒データベースへ書き込まない。

画面ロックや別アプリへの移動では自動停止させず、再表示時に経過時間を反映する。この時刻は中断時間を含むQ開始からの経過時間であり、公式の競技時間とは一致させない。端末時刻の変更も含めて復元を検証し、不自然な差分は無言で確定しない。

**UIの設計基準**

スマホ縦持ちを優先する。白地、濃い文字、枠のあるボタンで構成し、色だけで操作や状態を伝えない。本文は16px以上、操作ボタンは高さ48px以上を目安にする。Qと「開始から」の経過時間を上部、4つのプレーボタンを2列、直前の記録を下に置く。Q終了と試合終了は頻繁に押すプレーボタンから離す。選手選択時もQと経過時間が分かるようにする。

「保存済み」「未送信 3件」「保存できません」を区別する。通信待ちの間も次の記録を妨げない。小さいアイコンだけの操作、長押し、スワイプ必須の操作、派手なアニメーションは使わない。画面幅360〜430px程度で横スクロールせずに操作できることを確認する。

**技術構成**

| 役割 | 採用案 | 理由 |
| --- | --- | --- |
| 画面 | React + TypeScript + Vite | スマホ上の操作と状態管理を中心とした構成にする |
| 見た目 | 通常のCSS | 必要な画面とボタンを少ない依存関係で実装する |
| 公開 | Vercel | 既存GitHubリポジトリと連携する |
| データ | Cloud Firestore | 端末内キャッシュとクラウド同期を使う |
| 認証 | VercelのチームAPI＋Firebase Custom Authentication | 合言葉の照合とトークン発行をサーバーで行い、利用者はメール不要で入れる |
| アクセス制御 | Firestore Security Rules | 画面を迂回したアクセスも制限する |
| オフライン再表示 | Service Workerによるアプリ本体のキャッシュ | 読み込み済みのアプリを通信断でも再表示する |
| 検証 | 状態遷移テスト、Firebase Emulator、ブラウザ操作・スマホ実機確認 | 時計、保存、認証を重点的に確認する |

Vercelに公開しただけでは試合記録は保存されない。VercelにはNeonやSupabase等のデータベースをMarketplace経由で接続する仕組みがある。今回は合意済みのFirebaseに保存するので、Vercel側で別のデータベースを追加する必要はない。

**合言葉でのアクセス**

利用者には「合言葉」だけを入力してもらう。Vercel APIで合言葉を照合し、チームID入りのFirebaseカスタムトークンを発行する。メールを使ったユーザー作成やメール認証の有効化は不要。作成時はFirestoreトランザクションで使用済みの合言葉を拒否する。

選手・マネージャー個人のGoogleアカウントは不要。ユーザーの指定どおり、合言葉を知る利用者全員が同じチームの閲覧・編集権限を持つ。個人別の操作履歴や権限管理は初版では作らない。

データベース側では、トークンに入ったチームIDと有効なメンバーUIDが一致する場合だけアクセスを許可する。合言葉の索引と試行回数のコレクションはクライアントから読み書きできない。Vercel側からGoogleへの接続はこのアプリ専用のOIDC短期認証とする。具体的な権限設定はauth-deployment.mdに記載済み。

合言葉の本文は保存せず、サーバー専用の秘密値でHMACを計算して索引とする。初版には合言葉の変更やメールでの再発行機能を設けない。ログアウト時は未送信データを確認し、送信前に端末キャッシュを削除しない。端末に残ったキャッシュは遠隔では消去できないことを踏まえ、利用者本人が管理するスマホで使う。

**保存するデータ**

| 単位 | 主な項目 |
| --- | --- |
| 部活・アクセス設定 | 部活ID、名称、許可された認証UID |
| 選手 | 選手ID、表示名、背番号、利用中/非表示 |
| 試合 | 試合ID、日付、対戦相手、状態、作成日時 |
| 試合の選手名簿 | 選手ID、その試合時点の名前・背番号 |
| 各Qの時計 | Q番号、開始時刻、終了時刻、計測状態 |
| プレー | 一意なID、入力順、Q、Q開始からの経過時間、選手ID、プレー種別、シュート種別、作成・更新・取消情報 |

試合単位の選手名簿を保存するので、翌年度に名前や背番号を変更しても過去の記録は変わらない。プレーは1件ごとの独立したデータとして保存し、試合全体の巨大な配列を書き換えない。同時刻のプレーは入力順で並べる。同期された時刻とプレー発生時の試合時計を混同しない。

**通信断・再読み込み・複数端末**

FirestoreのWeb向け永続キャッシュを明示的に有効化する。最初のログインと試合準備はオンラインで行い、準備済みの試合は通信断でも記録できる設計にする。アプリ本体のキャッシュはFirestoreの機能とは別に用意する。未取得の過去試合までオフラインで読めるとは扱わない。

記録は端末へ反映し、クラウド同期の完了を別に表示する。試合を終了しても未送信なら「終了・未送信」と分かるようにする。認証切れや権限エラーを単なる通信待ちと区別する。端末データが消去されると未送信データは復旧できないため、試合後の同期確認を運用に含める。

全員が閲覧・編集できるが、1試合の入力は1端末で行うという運用を守る。複数端末のオフライン同時編集を完全調停する構成にはしない。試合途中の別端末への引き継ぎはQ間に同期確認後に行い、未送信のまま引き継がない。

Service Workerの更新で試合中に強制再読み込みしない。アプリ更新は記録中の試合が落ち着いた時点で反映する。

開発にはcodex/から始まる作業ブランチを使い、まとまった変更で関係する確認を実施しcommit・pushする。作業ブランチのVercelプレビューで確認し、本番へ反映する。Firestore Rulesの反映はVercelの画面デプロイとは別作業として確認する。

実データを使った試験を避け、ローカルのFirebase Emulatorと開発用Firebaseプロジェクトで試験する。本番用と開発用の接続先を分ける。パスワード、管理者認証鍵、選手の実データはGitへ入れない。必要な設定名だけ.env.exampleに記載する。

**重点的な受け入れ確認**

- 時間設定なしで第1Qを00:00から開始し、8分・10分を超えても計測が続く。
- 経過05:32でプレーボタンを押し、5秒後に選手・種別を決めても05:32で記録される。
- ボールアウト、タイムアウト、フリースローの際に時計を操作せず、その間も経過時間が進む。
- Qを手動で終了し、休憩後に次のQが00:00から始まる。休憩時間は前後のQに加算されない。
- 次のQを開始する前にQ終了を取り消した場合、元の開始時刻から計測を継続する。
- 画面ロックや再読み込みを挟んでも、Qの開始時刻を保持して経過時間を復元できる。
- 2点・3点・フリースローの成功・失敗、リバウンド、パスカットが正しく保存される。
- 選手の選び直し、キャンセル、直前取消、履歴訂正が意図どおりに働く。
- 連打、戻る操作、再読み込みで二重記録されない。
- 通信を切った状態で20件入力し、再表示・再接続後も20件が重複なく残る。
- 保存不能、認証切れ、未送信状態を「保存済み」と誤表示しない。
- 名前・背番号を変更しても過去試合の表記が変わらない。
- 未認証や無関係なアカウントからの読み書き、所属情報の自己変更を拒否する。
- 同期後、別のスマホで同じ履歴を閲覧できる。
- iPhone SafariとAndroid Chromeの対象端末で入力、ロック復帰、ログイン、通信断を確認する。実機未確認の環境は未確認と明記する。

**公開と費用**

Vercel・Firebaseは利用者の管理するアカウントで作成・接続する。Firebaseは無料のSparkプランを出発点にし、有料プランへの切替は別途判断する。Firestore無料枠は現時点で保存1GiB、読み取り5万回/日、書き込み2万回/日。無料枠でも利用上限はあるため、無制限とは扱わない。

時計の毎秒更新は端末で行い、書き込みはプレーや時計操作時に限る。例えば1試合300プレーならプレー追加分は概ね300書き込みで、ほかに時計・試合設定・訂正等が加わる。履歴は試合一覧をページ単位で取得し、全試合の全プレーを毎回読む構成にしない。

Vercel Hobbyは個人・非商用用途が対象。個人制作の部活用アプリとしての利用条件を接続時に確認する。Firestoreのクラウド保存は独立したバックアップとは異なり、自動バックアップ等には別途課金対象の機能がある。初版では削除を抑えた設計とし、長期保管用の書き出しが必要なら追加範囲として相談する。

**現在の状態**

記録機能とメール不要のチーム作成・参加、チームごとのデータ分離を実装して公開した。専用サービスアカウント・OIDC・IAMを設定済み。ローカルのAuth・Firestoreエミュレーターと実ブラウザに加え、実際のプレビューと本番のFirebase接続で作成、重複拒否、再参加、別チームからのアクセス拒否を確認した。検証用のチーム・選手・認証ユーザーは削除済み。
