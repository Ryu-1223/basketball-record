# バスケの記録

スマホで使う、バスケ部の試合記録アプリ。

画面上部の「試合の記録」「過去の記録」「チーム情報」「使い方」で切り替えます。終了した試合は「過去の記録」、選手登録は「チーム情報」から開けます。タブ移動中も記録中の試合と時計を保持します。

- 選手の名前・背番号を登録し、試合ごとにベンチ入り選手を選択。
- Q開始からの経過時間を計測。一時停止と再開ができ、停止中もプレーを記録できます。
- シュート成功・失敗（2点／3点／フリースロー）、リバウンド、パスカットを記録。
- 記録の取り消し・訂正、過去試合の閲覧。
- 試合の削除。終了後の「その他の操作」、開始前・記録中の「試合の管理」から確認して削除できます。試合内のプレーも削除され、元には戻せません。
- ファウル・タイムアウト・初出場、TOスコアシートと選手別成績のA4 PDF出力。[使い方と対応範囲](docs/scoresheet.md)
- 「チームを作成」「チームに参加」から、メール不要でアクセス。作成時はチーム名と合言葉、参加時は合言葉を入力。
- 同じ合言葉でチームを重複作成できず、選手・試合はチームごとに保存・共有。
- 通信断中の入力と再送、読み込み済みアプリのオフライン再表示。

## 開発環境

Node.js 24.13以上を使用します。

```sh
npm ci
npm run dev
```

開発サーバーは `http://127.0.0.1:5173/`。チーム認証APIも含めて検証する場合は、別々のターミナルで `npm run emulators` と `npm run dev:emulator` を実行します（Java 21以上が必要）。本番の認証設定を使わず、作成・参加とチームごとの記録を確認できます。

## 共有保存と公開

[接続・公開手順](docs/setup.md)と[認証APIの権限設定](docs/auth-deployment.md)を参照してください。FirebaseのWeb接続情報は `.env.local` に設定します。サーバー側はVercelの短期OIDC認証を使う構成で、Googleの秘密鍵は発行しません。合言葉本文はFirestoreのチーム情報に平文保存し、参加済みメンバーが確認できます。Gitや環境変数には保存しません。既存チームは次の参加時に本文が保存されます。

## 検証

```sh
npm test
npm run build
npm run test:rules
```

`test:rules` はJava 21以上が必要です。実プロジェクトには接続せず、`demo-basketball-record` のFirestoreエミュレーターを使います。GitHub Actionsでも画面操作テスト・ビルド・アクセスルールを確認します。

## 運用

試合の入力は1試合1台で行ってください。「すべて保存済み」を確認してから退出・端末変更してください。端末のブラウザデータを消去すると未送信の記録は失われます。試合中はアプリ更新を強制反映しません。

時刻はQ開始からの経過時間で、一時停止中の時間を除きます。公式の競技時計とは連動しません。選手登録を変更しても、既存の試合に保存した名簿は変わりません。

## 試合結果と相手の得点

相手の得点は背番号とシュート種類を試合中に記録します。試合終了後はシュート・パスカット・リバウンド・相手得点を集計し、記録一覧から訂正できます。この機能の追加前に作られた試合では相手得点を未記録と表示します。


## 部内ゲームと成績の確認

「新しい試合」から「部内ゲーム」を選び、参加者のチーム２チェックでチーム１・チーム２に分けます。得点だけ、チーム１の個人成績、両チームの個人成績のいずれかを選べます。記録画面では対象の組を切り替えます。終了後の「次の試合を準備」で選手・相手・組分けを確認してから作成できます。同日・同じ連続ゲームの読み込み済み記録を「この連続ゲームの合計」で見られます。成績は記録された分の集計で、記録対象外の項目は未記録です。

試合中も「途中成績を見る」で確認できます。個人成績は記録がなく未確認の欄を「—」と表示し、全件を確認した場合だけ項目ごとに「確認済み」にできます。得点者が分からないときは「選手不明」または「背番号不明」で得点を残し、後から訂正できます。直前の取消や試合終了を元に戻す操作もあります。

試合一覧から日付・対戦相手で絞り込めます。試合一覧の「ゴミ箱へ」で移動し、「ゴミ箱を見る」から30日以内なら戻せます。端末の画面消灯を抑える操作は試合画面下の「この試合の選手」内にあります。端末の状態によっては利用できません。

ゲームデータは従来形式を読み取ります。試合ごとの選手追加・名前・背番号の訂正は自チーム側に対応し、他の試合の名簿は変更しません。通信断やリロード後は画面上部の保存状態を確認してから端末を切り替えてください。部内ゲームの連続ゲーム合計は一覧に読み込まれた同一セッションの試合を対象とし、途中で「前の試合をもっと見る」が必要な場合があります。

## ゴミ箱と自動削除

試合一覧の「ゴミ箱へ」で30日間復元できる状態へ移します。保管済みの試合も通常の一覧へ表示し、旧 archived フィールドは互換用に残します。ゴミ箱の試合は成績・連続ゲームの集計から除外し、閲覧だけできます。選手名簿と出力済みPDFは削除しません。

移動・復元は認証付き `/api/game`（DELETE＝移動、POST＝復元）でサーバートランザクションを実行します。旧クライアントのDELETEも即時完全削除をしません。試合の世代を移動時に更新し、ゴミ箱内の書き込みと、復元後の古い世代の書き込みはFirestoreルールで拒否します。サーバーでゴミ箱・世代変更・完全削除を確認できた送信待ちだけを破棄します。確認できない未送信データは保持します。

本番の環境変数 `CRON_SECRET` を32バイト以上のランダム値で設定します（ログに出さないこと）。`vercel.json` のCronが毎日18:00 UTC（日本時間03:00の時間帯）に `/api/cleanup-games` を呼びます。認証のない呼び出しは拒否します。30日ちょうどから復元不可となり、通常はその後1日程度でデータ本体を削除します。無料枠の読み書き・削除・実行量を使用します。

`_gameTrash` はサーバー専用の期限順キューです。完全削除の前に `deletedGames` へ印を付け、復元との競合と古い端末による再作成を防ぎます。プレーを含む再帰削除に失敗してもキューを残し、次回同じ処理を再実行します。完全削除後の印には試合内容・選手名を保存しません。

VercelのFunctionsログとCronの実行履歴で失敗を確認できます。再実行はVercelのCron画面、または同じ認証ヘッダー付きGETで行います。応答の `remaining: true` は期限切れの処理待ちが残っている状態です。大量の削除では再実行してください。試用モードは端末内に保存し、起動時と起動中の定期処理で期限切れを削除します。
